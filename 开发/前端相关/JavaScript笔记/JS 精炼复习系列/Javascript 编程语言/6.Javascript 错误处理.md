通常，如果发生错误，脚本就会“死亡”（立即停止），并在控制台将错误打印出来。而错误处理是开发健壮应用程序的关键部分。

## 错误类型

在 JavaScript 中，错误可以分为两大类。这两类错误发生在代码执行的不同阶段，具有不同的特点和调试方式。

1. **解析时错误（Parse-time Errors）**：发生在 JavaScript 引擎解析（编译）代码的阶段，此时代码尚未开始执行。
   - 发生在代码执行之前，通常是语法错误，会导致整个脚本无法执行。
   - 在开发环境中通常会被编辑器立即发现。
2. **运行时错误（Runtime Errors/Exceptions）**：发生在代码执行阶段，当JavaScript引擎尝试执行无效操作时抛出。
   - 发生在代码执行过程中，代码语法正确，但执行逻辑有问题。
   - 若不处理，可能导致程序部分或完全停止运行。
   - 可以使用`try-catch`捕获和处理。

开发时，我们要自行处理解析时错误，而程序运行时可能抛出的各种错误则我们制作一个错误处理程序来关注。



## 错误捕获

`try...catch...finally`，可以**捕获**错误，因此脚本可以执行更合理的操作，而不是直接终结运行。

```js
try {
   // ... 尝试执行的代码 ...
} catch (err) {
   // ... 处理 error ...
} finally {
   // ... 总是会执行的代码 ...
}
```

1. 首先，执行 `try {...}` 中的代码。
2. 如果这里没有错误，则忽略 `catch (err)`：执行到 `try` 的末尾并跳过 `catch` 继续执行。
3. 如果这里出现错误，则 `try` 执行停止，控制流转向 `catch (err)` 的开头。变量 `err`（我们可以使用任何名称）将包含一个 error 对象，该对象包含了所发生事件的详细信息。
4. 无论是否出现错误，最后 `finally` 中的语句都会执行。

### 可选的 catch 参数

最近，Js 新增了一个特性 ：如果我们不需要 `error` 的详细信息，`catch` 也可以忽略它。

```js
try {
  // ...
} catch { // <-- 没有 (err)
  // ...
}
```

### 全局 catch

有时，我们想在一些错误未被局部捕获或我们想在全局环境来处理所有错误而不会使脚本停止。

**规范中没有相关内容**，但是代码的执行环境一般会提供这种机制，因为它确实很有用。

1. **事件监听器**：使用 `addEventListener` 监听 `error` 事件。

   ```js
   window.addEventListener('error', function(event) {
     console.error('全局错误捕获:', {
       message: event.message,
       filename: event.filename,
       lineno: event.lineno,
       colno: event.colno,
       error: event.error
     });
     
     // 可以阻止默认行为
     // event.preventDefault();
   });

2. **浏览器环境**：使用 `window.onerror` 监听 `error` 事件。

   ```js
   window.onerror = function(message, source, lineno, colno, error) {
     console.log('全局错误捕获:', {
       message,    // 错误信息
       source,     // 发生错误的脚本URL
       lineno,     // 行号
       colno,      // 列号
       error       // 错误对象（可能为undefined）
     });
     
     // 返回true可阻止浏览器默认错误处理
     return true;
   };
   ```

3. **Node.JS 环境**：使用 `process.on("uncaughtException")` 语句，监听 `uncaughtException` 事件。

   ```js
   process.on('uncaughtException', (error) => {
     console.error('未捕获的异常:', error);
     
     // 通常建议记录错误后退出进程
     // process.exit(1);
   });

4. **Promise 的全局错误处理**：监听 `unhandledrejection` 事件。

   ```js
   window.addEventListener('unhandledrejection', function(event) {
     console.error('未处理的Promise拒绝:', event.reason);
     // 可以阻止默认行为（避免控制台报错）
     // event.preventDefault();
   });
   
   process.on('unhandledRejection', (reason, promise) => {
     console.error('未处理的Promise拒绝:', reason);
   });

### 捕获失效的情况

1. **语法错误**：代码无法解析，脚本无法运行。
2. **异步代码中的错误**：
   1. 定时器 `setTimeout` 回调中的错误，需在回调函数内另外放置错误捕获程序。
   2. `Promise` 未被捕获的拒绝，需用 `Promise` 自己的错误捕获 API。
   3. `async`/`await` 未捕获的异常，其返回的是 `Promise` 对象，也要用对应的 API。
3. **跨域脚本错误**：浏览器出于安全限制，只能通过 `window.onerror` 获取有限信息。
4. **Web Worker 中的错误**：发生在另外的作用域，但是能通过 `window.onerror` 获取信息。



## Error 对象

发生错误时，JavaScript 会生成一个包含有关此 error 详细信息的对象。

所有内建的 error 对象都具有**两个主要属性**：

- `name`：Error 名称，一般存储的是错误类型对象的构造器的名字。
- `message`：关于 error 的详细文字描述。

还有其他非标准的属性在大多数环境中可用，如其中被最广泛使用和支持的：

- `stack`：表示当前的调用栈，用于调试目的的一个字符串，其中包含有关导致 error 的嵌套调用序列的信息。

```js
try {
    lalala;             // error, variable is not defined!
} catch (err) {
    alert(err.name);    // ReferenceError
    alert(err.message); // lalala is not defined
    alert(err.stack);   // ReferenceError: lalala is not defined at (...call stack)

    // error 信息被转换为像 "name: message" 这样的字符串
    alert(err); // ReferenceError: lalala is not defined
}
```

### 常见内建错误类型

1. ReferenceError（引用错误）

   ```javascript
   console.log(neverDeclaredVariable); // 引用未声明的变量
   ```

2. TypeError（类型错误）

   ```javascript
   const foo = null;
   foo.bar(); // 尝试访问null的属性或方法
   
   const num = 123;
   num.toUpperCase(); // 错误的方法调用
   ```

3. RangeError（范围错误）

   ```javascript
   new Array(-1); // 无效的数组长度
   ```

4. URIError（URI错误）

   ```javascript
   decodeURIComponent('%'); // 无效的URI编码
   ```

### 新建内建的错误对象

对构造函数 `Error(message)` 使用 `new` 的方式，即可创建一个新的错误对象。

1. 基本创建方式

   ```javascript
   // 通用错误
   const genericError = new Error('发生了一个错误');
   
   // 带堆栈限制（减少堆栈深度）
   const limitedStackError = new Error('限制堆栈深度');
   Error.captureStackTrace(limitedStackError, someFunction);
   
   // 包含额外属性的错误
   const detailedError = new Error('验证失败');
   detailedError.statusCode = 400;
   detailedError.timestamp = new Date();
   ```

2. 创建内置类型错误

   ```js
   // 引用错误
   const refError = new ReferenceError('变量未定义');
   
   // 类型错误
   const typeError = new TypeError('不是函数');
   
   // 范围错误
   const rangeError = new RangeError('无效数组长度');
   
   // URI错误
   const uriError = new URIError('非法URI字符');
   
   // 语法错误（通常由引擎抛出）
   const syntaxError = new SyntaxError('意外的标识符');



## 抛出错误

`throw` 操作符用于生成并抛出一个错误对象，中断当前执行流程并跳转到错误处理程序：

```js
throw new Error("发生了一个错误");
```

### 再次抛出（Rethrowing）

`catch` 会捕获所有错误。但若希望一个 `catch` 程序只处理我们预知的可能错误，而其他未知的错误再交给外部的错误未知程序，这就要用到**再次抛出**的方法。

先需要判断错误类型并进行处理，未知的错误类型则在该 `catch` 块内再次抛出。

可通过以下方式判断错误类型：

1. 通常可用 `instanceof` 操作符。
2. `error.name` 或 `error.constructor.name` 。

```js
try {
  user = { /*...*/ };
} catch (err) {
  // 通过 instanceof 判断
  if (err instanceof ReferenceError) {/*...*/}
  // 通过 error.name 判断
  else if (err.name === 'RangeError') {/*...*/}
  // 未知错误再次抛出
  else{
    throw err;
  }
}
```



## 自定义错误

在大型应用开发中，自定义错误类能提供更精确的错误分类和更丰富的上下文信息，通常用在自己开发的第三方库，携带业务相关的附加数据。

我们自定义的 error 应该支持基本的 error 的属性，例如 `message`，`name`，并且最好还有 `stack`。

```js
class MyError {
  constructor(message) {
    this.message = message;
    this.name = "Error"; // (不同的内建 error 类有不同的名字)
    this.stack = <call stack>; // 非标准的，但大多数环境都支持它
  }
}
```

### 扩展 Error

可通过继承内建 `Error` 来在原有内容的基础上，拓展自定义错误的能力。

JavaScript 允许将 `throw` 与任何参数一起使用，所以技术上自定义的 `error` 不需要从 Error 中继承。

但若使用继承，就可以使用 `obj instanceof Error` 来识别 error 对象。因此最好使用继承。

```js
class ValidationError extends Error {
  constructor(message) {
    super(message);
    this.name = "ValidationError";
  }
}
```

上例中，我们自定义了一个“校验错误”。我们将其重命名为 `ValidationError` 。

以下代码是一个应用场景。我们在函数中接收一个 json 并解析，如果解析结果中不包含某些对象属性则抛出“校验错误”。

```js
function readUser(json) {
    let user = JSON.parse(json);

    if (!user.age) {
        throw new ValidationError("No field: age");
    }
    if (!user.name) {
        throw new ValidationError("No field: name");
    }

    return user;
}

try {
    let user = readUser('{ "age": 25 }');
} catch (err) {
    if (err instanceof ValidationError) {
        alert("Invalid data: " + err.message); // Invalid data: No field: name
    } else if (err instanceof SyntaxError) {
        alert("JSON Syntax Error: " + err.message);
    } else {
        throw err;
    }
}
```

### 深入继承

随着开发的应用程序的增长，我们自己的 error 自然会形成形成一个层次结构（hierarchy）。

```js
class ValidationError extends Error {
  constructor(message) {
    super(message);
    this.name = "ValidationError";
  }
}

class PropertyRequiredError extends ValidationError {
  constructor(property) {
    super("No property: " + property);
    this.name = "PropertyRequiredError";
    this.property = property;
  }
}
```

`ValidationError` 类是非常通用的，错误信息完全根据构造时传入的信息，其还可以细化。

上例中，我们继承`ValidationError` 类制作更具体的 `PropertyRequiredError` 类，其只需要传入缺失的属性名，更加便利。

```js
let jsonProps = ['age', 'name', 'from']

function readUser(json) {
    let user = JSON.parse(json);

    for (let prop of jsonProps)
        if (!user[prop])
            throw new PropertyRequiredError(prop);
}

try {
    let user = readUser('{ "age": 25, "from": "China"}');
} catch (err) {
    if (err instanceof ValidationError) {
        alert("Invalid data: " + err.message); // Invalid data: No property: name
        alert(err.name); 					 // PropertyRequiredError
        alert(err.property); 			      // name
    }
}
```

#### 自动更改错误名称

注意到上例的写法中，每次的 `this.name` 是通过手动重新赋值的，显得不够优雅。

可通过创建一个“**基础错误（basic error）**”类，进行 `this.name = this.constructor.name` 赋值，然后让所有自定义的 `error` 都从这个“基础错误”类进行继承。

这样，之后每次继承时就会通过 `super` 将当前错误名称改为构造器的名称，避免重复劳动。

```js
class MyError extends Error {
  constructor(message) {
    super(message);
    this.name = this.constructor.name;  // 将其赋值为构造器的名称
  }
}

class ValidationError extends MyError { }

class PropertyRequiredError extends ValidationError {
  constructor(property) {
    super("No property: " + property);
    this.property = property;
  }
}

alert( new ValidationError("test").name );        // ValidationError
alert( new PropertyRequiredError("field").name ); // PropertyRequiredError
```
