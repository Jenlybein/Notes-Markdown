## 模块简介

随着我们的应用越来越大，我们想要将其拆分成多个文件，即所谓的“**模块（module）**”。

模块化编程是一种将复杂系统分解为独立、可复用组件的软件开发方法。在JavaScript生态中，模块化经历了从无到有、从混乱到规范的发展历程，最终形成了现代前端工程化的基石。

简单来说，一个模块（module）就是一个文件。一个脚本就是一个模块。

模块化的核心价值体现在：

1. **代码组织**：将功能拆分为独立单元，提高可维护性
2. **依赖管理**：明确声明模块间关系，避免全局污染
3. **复用性**：模块可跨项目复用，提高开发效率
4. **命名空间**：隔离作用域，避免命名冲突
5. **按需加载**：优化资源加载策略，提升性能



### 模块的发展历程

#### 最初的设计

在早期的 Javascript 中并未考虑大型应用开发，缺乏模块系统，开发者只能通过多个脚本文件分割代码：

```js
// utils.js
function formatDate() { /* ... */ }

// user.js
function getUser() {
  formatDate(); // 隐式依赖
}

// 页面中
<script src="utils.js"></script>
<script src="user.js"></script>
```

这种模式存在三大致命缺陷：

1. 所有函数都挂在全局对象上，极易命名冲突
2. 脚本加载顺序必须手动维护
3. 无法知道文件之间的依赖关系
4. 私有变量可能被外部修改

为了解决上述缺陷，开发者们用 **立即执行函数表达式(IIFE)** 的形式：

```js
// 模块定义
var myModule = (function() {
  var privateVar = '秘密';
  
  function privateMethod() {
    console.log(privateVar);
  }

  return {
    publicMethod: function() {
      privateMethod();
    }
  };
})();

// 使用模块
myModule.publicMethod();
```

- 利用函数作用域创建私有空间
- 通过闭包保护私有变量，对外不可见
- 返回的对象作为公共接口
- 模块初始化在定义时完成

#### CommonJS 规范

**CommonJS** 是由社区提出的一种 JavaScript 的模块化方案，并由 Node.js 借鉴与实现。主要通过 `require()` 、`module.exports` 实现模块的导入和导出。

CommonJS 的出现，催生了npm生态系统，典型的 Node 项目将第三方模块添加在 `node_modules` 文件夹。

#### ES6 规范

语言级的模块系统在 2015 年的时候出现在 ES6 中，此后逐渐发展，现在已经得到了所有主流浏览器和 Node.js 的支持。

ES 模块的出现意味着 JavaScript 模块化方案的成熟，服务器和浏览器的模块化方案因此得到统一。

## ES6 模块

每个ES模块都是一个独立的文件，模块内部的所有变量和函数默认不暴露到全局作用域。

### 模块的特性

1. 每个文件自动成为独立模块
2. 严格模式"`use strict`"默认启用，模块始终在严格模式下运行。
3. 每个模块都有自己的模块级作用域（非全局作用域）。若要声明一个全局变量，可用全局对象(如 window )，这样可以突破模块作用域。
4. 如果同一个模块被导入到多个其他位置，那么它的代码只会执行一次，即在第一次被导入时。可利用该特性实现模块的初始化。
5. 模块中的 `this` 是 `undefined`。
6. 导入的变量是只读的（类似 `const`），不能直接重新赋值（但可以修改对象属性）。
7. 支持静态分析和编译时优化
8. 支持循环依赖的合理处理

### 导出机制

1. **命名导出**

   ```js
   // 方式1：逐个导出
   export const name = 'value';
   export function func() {};
   
   // 方式2：统一导出列表
   const var1 = 'value';
   function func1() {};
   class Class1 {};
   export { var1, func1, Class1 };
   
   // 方式3：用 as 重命名导出
   export { var1 as renamedVar, func1 as renamedFunc };
   export { sayHi as default};  // 与 "export default" 效果一样
   ```

   - 一个模块可以有多个命名导出
   - 导入时需要知道具体导出名称
   - 支持导出时重命名
   - 适合工具类模块（导出多个实用函数）

2. **默认导出**

   ```js
   // 方式1：直接默认导出
   export default function() {};
   export default 42;
   
   // 方式2：先定义后默认导出
   function func() {};
   export default func;
   
   // 方式3：默认导出对象
   export default { name: 'value' };
   ```

   - 每个模块只能有一个默认导出
   - 导入时可自定义名称
   - 语法更简洁
   - 适合主功能模块（如React组件）

3. **复合导出**

   ```js
   // 重新导出其他模块的内容
   export * from './moduleA.js';           // 导出所有命名导出（不包括默认导出）
   export { name } from './moduleB.js';    // 选择性重新导出
   export { default } from './moduleC.js'; // 重新导出默认导出
   ```

   - 创建聚合模块(barrel module)
   - 实现模块继承模式
   - 构建公共接口层

### 导入机制

1. **基本导入**

   ```js
   // 导入命名导出（需用拓展运算符解析，命名需对应）
   import { export1, export2 } from './module.js';
   import { export1 as renamed } from './module.js';
   
   // 导入默认导出（命名可随意写入）
   import defaultExport from './module.js';
   
   // 混合导入
   import defaultExport, { namedExport } from './module.js';
   import defaultExport, * as namespace from './module.js';
   
   // 仅执行模块（不导入任何绑定）
   import './module.js';

2. **命名空间导入**：将所有内容导入为一个对象

   ```js
   import * as utils from './utils.js';
   utils.function1();
   utils.function2();
   let test = utils.default;      // 默认的导出
   ```

   - 需要导入模块的所有导出时
   - 避免命名冲突
   - 不确定具体需要哪些导出时

3. **HTML 中导入**：必须用 `<script type="module">` 标明此脚本应该被当作模块对待。

   ```html
   <!doctype html>
   <script type="module">
       import {sayHi} from './say.js';
       document.body.innerHTML = sayHi('John');
   </script>
   ```

   - 使用 `<script type="module">`导入总是如使用了 `<script defer>` 一般，是被延迟的，不会阻塞 HTML 的处理，等到 HTML 文档完全准备就绪才执行。
   - 对于非模块脚本，`<script async>` 仅适用于外部脚本（带 `src` 的 `<script>`)。但 `async` 也适用于对于内联的模块脚本。异步脚本会在准备好后立即运行。
   - 具有相同 `src` 的外部脚本仅运行一次。

4. **动态导入**：使用 `import(...)` 语句加载模块，返回一个 promise。

   ```js
   // 返回Promise
   import('./module.js')
     .then(module => {
       module.default();
       module.namedExport();
     });
   
   // 在async函数中
   async function load() {
     const module = await import('./module.js');
   }
   ```

   - 按需加载（代码分割）
   - 条件加载
   - 运行时决定加载路径
   - 错误处理更灵活

### 模块作用域

JavaScript 的模块作用域是通过一套精密的底层机制实现的，与传统的脚本作用域有本质区别。

####  模块执行上下文

当 JavaScript 引擎加载一个模块时，会创建一个 模块执行上下文，其结构与普通执行上下文不同：

- **没有变量环境（Variable Environment）**：模块中 `var` 声明的变量直接存储在模块环境记录中。
- **词法环境（Lexical Environment）**：用于管理模块内的 `let`/`const` 声明。
- **this 绑定**：设计为 undefined。模块的顶层作用域被视为一个“独立”的上下文，没有隐式的 `this` 绑定。

```js
ModuleExecutionContext = {
  LexicalEnvironment: {
    EnvironmentRecord: {
      type: "module", // 标识为模块环境记录
      // 存储 import/export 绑定
      message: "Hello" (来自模块导出),
      // 模块内的 let/const 也存储在此
      localVar: <uninitialized> → 42
    },
    OuterLexicalEnvironment: null // 模块作用域独立，无外部引用
  },
  ThisBinding: undefined // 模块顶层 this 是 undefined
}
```

#### 模块词法环境

- **模块环境记录（Module Environment Record）**
  - 是声明式环境记录（Declarative Environment Record）的子类，与函数/块级作用域的环境记录不同。
  - 存储模块内部的所有变量、函数、类声明（包括 `let`、`const`、`function` 等）
  - 管理导入和导出的绑定关系（如 `import { x } from 'module'` 会创建一个只读绑定）
  - 建立本地变量与导出名称的关联（如 `localName → exportName`）。
  - 运行时变量的实际值（模块记录是静态描述结构，不涉及值；而环境记录存储运行时变量的实际值)。
- **外部词法环境引用（Outer Lexical Environment Reference）**
  - 模块词法环境的外部引用始终是 **`null`**，模块是独立的作用域。
  - 模块只能通过显式 `import` 访问其他模块的内容，而非通过作用域链。

模块环境记录（Module Environment Record）：核心部分，与其他环境记录不同，存储 `import`/`export`。

#### 模块环境记录

模块环境记录是 ES6 模块设计的一种**声明式环境记录**，用于管理模块作用域内的所有标识符绑定。其核心特点是：

1. 存储模块的 import / export 绑定关系
2. 默认启用严格模式
3. 完全隔离全局作用域
4. 通过不可变引用实现跨模块的实时绑定

```javascript
// 模块环境记录示例，用伪代码表示其典型结构：
ModuleEnvironmentRecord = {
    type: "module",
    // 存储导入绑定（只读）
    imports: new Map([
        ['message', { 
            value: 'Hello', 
            writable: false,  // 不可修改
            module: "./other.js" // 来源模块
        }]
    ]),
    // 存储导出绑定
    exports: new Map([
        ['data', {
            value: 42,        // 实际值在求值阶段填充
            mutable: true     // 是否允许修改
        }]
    ]),
    // 存储模块局部变量
    declarations: new Map([
        ['count', {
            value: 0,
            mutable: true
        }]
    ]),
    outer: null,  // 模块作用域独立
    [[Evaluated]]: false // 标记是否已执行
}
```

#### 模块记录

模块记录是模块的 **静态描述信息**，在代码解析阶段生成，用于存储模块的元数据和结构，不涉及运行时状态。

如有示例：

```js
// math.js（导出模块）
export const pi = 3.14;
export function square(x) { return x * x; }

// app.js（导入模块）
import { pi, square } from './math.js';
console.log(square(pi));
```

对应的模块记录存储内容：

- *导入条目（Import Entries）*：记录所有 `import` 语句的静态信息：

  ```javascript
  // app.js 的模块记录会记录所有导入依赖关系：
  {
    moduleSpecifier: "./app.js",
    sourceCode: "import { pi, square } from './math.js'; ...",
      
    // 导入条目（Import Entries）
    imports: [
      {
        moduleSpecifier: "./math.js",  // 导入的模块路径
        importName: "pi",             // 从 math.js 导入的变量名
        localName: "pi"               // 绑定到本地的名称
      },
      {
        moduleSpecifier: "./math.js",
        importName: "square",
        localName: "square"
      }
    ],
    // 其他元数据
    moduleSpecifier: "./app.js",
    sourceCode: "import { pi, square } from './math.js'; ..."
  }
  ```

- *导出条目（Export Entries）*：记录所有 `export` 语句的静态信息：

  ```javascript
  // 在解析阶段，引擎会为 math.js 生成如下模块记录（伪代码）：
  {
    moduleSpecifier: "./math.js",
    sourceCode: "export const pi = 3.14; export function square(x) {...}",
    
    // 导出条目（Export Entries）
    exports: [
      {
        exportName: "pi",       // 对外导出的名称
        localName: "pi",        // 对应的本地变量名
        isDefault: false        // 非默认导出
      },
      {
        exportName: "square",   // 对外导出的名称
        localName: "square",    // 对应的本地变量名
        isDefault: false        // 非默认导出
      }
    ],
    // 其他元数据（如模块路径、源代码等）
    moduleSpecifier: "./math.js",
    sourceCode: "export const pi = 3.14; export function square(x) {...}"
  }
  ```

- *模块源代码*：原始代码的抽象语法树（AST）或可执行字节码。

### 模块工作流程

如有示例如下：

```js
// counter.js
export let count = 0;
export function increment() {
  count++;
}

// logger.js
import { count } from './counter.js';
export function log() {
  console.log(`Current count: ${count}`);
}

// main.js
import { increment } from './counter.js';
import { log } from './logger.js';

increment();
increment();
log();
```

1. **模块图构建**

   发现 `<script type="module" src="main.js">`，开始通过解析器构建模块依赖图（DAG）：

   ```js
   main.js
    ├──> counter.js
    └──> logger.js
            └──> counter.js (再次导入，但会复用缓存)

2. **解析并构建结构信息**

   对每个模块进行词法分析、语法分析，构建 AST（抽象语法树），发现 `import`、`export` 等关键结构。

3. **模块记录创建**

   - 模块 URL / 路径
   - 所有导出的绑定（exported bindings）
   - 所有依赖模块（imported modules）
   - 初始化状态（未实例化、已实例化、已执行等）

   ```js
   ModuleRecord for counter.js:
     exports: [count, increment]
     imports: []
   ModuleRecord for logger.js:
     exports: [log]
     imports: [count from counter.js]

4. **模块实例化**

   1. 创建执行上下文

   2. 构建模块环境记录

      - 声明并注册所有 `import/export` 的绑定（未赋值，相当于变量声明提升）
      - 创建只读绑定（imported binding 只读）

      1. counter.js 绑定：`count`和`increment`，初始为 uninitialized

         ```js
         ModuleExecutionContext
           ├── LexicalEnvironment
           │   ├── count (binding, live, mutable)
           │   └── increment (binding, live, immutable)

      2. logger.js ：从 counter.js 获取 count 的绑定引用（注意是引用不是变量），所以之后 counter.js 中更新 count 的值，则 logger.js 中获得的 count 的值也会变化。

5. **模块执行**：执行引擎运行 AST，填充值

   - 此时正式进入模块执行上下文，运行模块代码
   - 所有绑定变量被初始化赋值
     - 示例中，`count` 绑定被赋值为 `0`，`increment()` 函数定义完成。
   - 导出的变量变为可访问状态（含实时绑定）

6. **模块命名空间对象构建**：模块对象内部存储隐藏的 `[[ModuleNamespace]]` 对象

   - 每个模块都自动创建一个只读的命名空间对象，不可增删属性，属性为实时绑定。
   - 可以通过 `import * as mod from './mod.js'` 访问模块命名空间对象。
   - 所有导出（包括函数、变量、类等）都作为只读属性存储在这里。

   ```js
   // counter.js 的 Module Namespace Object
   {
     count: 2, // getter 实时读取绑定值
     increment: ƒ
   }

7. **模块缓存**

   - 所有模块执行完后，其导出值被缓存在模块实例缓存表。
     - 缓存结构：
       - 模块 URL → 模块命名空间对象（或完整记录）
       - 保证所有 `import` 指向同一个实例
   - 单例机制：同一个模块无论被多少地方 `import`，只执行一次，后续从缓存中直接返回结果





## ES6 与 CommonJS 模块的差异

- CommonJS 模块输出的是一个值的拷贝，ES 模块输出的是值的引用。
- CommonJS 模块是运行时加载，ES 模块是编译时输出接口，ES 模块的加载效率要比 CommonJS 模块的高。。
- CommonJS 模块的 `require()` 是同步加载模块，ES 模块的 `import` 命令是异步加载，有一个独立的模块依赖的解析阶段。

CommonJS 模块和 ES 模块都支持模块的循环加载，他们的处理方式不一样，返回的结果也不一样。
